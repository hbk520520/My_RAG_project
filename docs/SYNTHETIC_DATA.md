# 离线合成训练数据

`model.data.synthetic` 生成带可执行标签的虚构资料核对任务，不调用模型 API、不下载权重、不访问服务。
仅使用标准库和已有 Pydantic；导入模块不生成数据。原有 Evol-Instruct API 入口与训练脚本保持不变。

## 范围与设计依据

已有 `model/data/evol_instruct.py` 使用模型生成问答、计划和场景；其模型输出不能单独充当已验证标签。
`benchmark_causal` 已有 SCM 领域评测，本组件不复制法律因果模型，也不修改该评测集。
新增组件处理来源核对、缺失信息、工具依赖和算术，为 Grader 与后续轨迹筛选提供独立数据入口。
任务规则是明确声明的虚构资料策略，不将虚构条款、金额或权威等级当作现实法律结论。

参考 [Kim 等，ACL 2026](https://aclanthology.org/2026.acl-long.1064/) 及其
[实验代码](https://github.com/kms0805/how-training-data-shapes-pk-ick) 的文档内复述、受控冲突和偏斜知识分布思想。
这些机制在本组件中是可配置的实验变量，不代表已验证其在法律 Agent 上改善训练。
默认复述率、冲突率均为零；不把论文特定条件下的冲突比例用作通用参数。

| 思路 | 本期实现 |
|---|---|
| 多任务混合 | lookup、aggregate、recovery、missing 的类别权重；不强行用高斯生成文字 |
| 长尾与复杂度 | 主题频率、目标记录数分别按有限范围的幂律权重采样；限制最多 24 条目标记录 |
| 复述 | 同一文档内增加语义复述，不增加独立来源或重复金额 |
| 冲突 | 较低级参考资料冲突可按环境规则消解；同级主资料冲突必须请求补证 |
| 条件生成 | 缺失任务的最后一个金额为空；恢复任务首次读取暂时失败；不随机拼接不合法属性 |
| 结构变化 | 打乱资料顺序、加入无关资料及工具；独立 OOD 组使用改名工具和改写问题 |
| 正确标签 | 从当前文档解析主资料的一致金额，用 Decimal 求和；变体重新计算标签 |
| 轨迹与奖励 | 模拟器逐步回放并核对观测，独立记录答案正确性、步骤有效性、调用数和奖励 |
| SFT / DPO / 评分数据 | 导出 Grader 聊天样本、偏好对、轨迹标量分数和同任务排序对；不执行训练 |

不在本期加入多 Agent、通用 SQL/浏览器模拟、任意工具格式替换、LLM 改写或自适应困难样本挖掘。
这些扩展需要相应可执行环境与验证器，不能直接套用当前标签。

## 使用

在项目根目录生成干净基线；输出目录必须是新目录，Windows 下限制在 D 盘：

```powershell
.\.venv\Scripts\python.exe -m model.data.synthetic --output 'D:\project(now)\outputs\synthetic\baseline-v1'
```

默认 100 个基础资料组、10 个独立 OOD 组，每组 2 个变体。组归属先通过稳定哈希确定，再生成变体；
同一实体及来源组不会因复述或冲突变体跨集合。基础组与 OOD 组使用不同 ID 命名空间，增加生成数量不改变已有组的身份。
train / validation / test 的默认比例是 0.8 / 0.1 / 0.1，实际数量受哈希和样本规模影响，不保证每个小规模集合非空。

通过 `--config D:/.../config.json` 指定部分配置，其余使用默认值，例如：

```json
{
  "seed": 42,
  "groups": 100,
  "ood_groups": 10,
  "variants": 2,
  "max_records": 12,
  "family_weights": {"lookup": 0.25, "aggregate": 0.35, "recovery": 0.2, "missing": 0.2},
  "repetition_rate": 0.5,
  "conflict_rate": 0.15,
  "unresolved_conflict_rate": 0.5
}
```

以上是困难样本配置示例，不是训练最优参数。冲突按非 missing 样本采样，复述按目标主文档采样；
`unresolved_conflict_rate` 是已注入冲突中同级冲突的概率。配置保存于 manifest，实际分布另行计数。

## 输出与训练边界

每个集合分别输出：

- `*.tasks.jsonl`：完整环境、来源组、变换和 `expected`，用于回放和审计；**不能整条直接作为模型输入**。
- `*.grader_sft.jsonl`：复用项目 `build_grader_messages`；助手标签符合 `Grade` 字段约定。
- `*.grader_dpo.jsonl`：`prompt/chosen/rejected`；负例明确标记为偏好候选，不混入正确 SFT 标签。
- `*.trajectories.jsonl`：程序参考、冗余读取、伪造观测、错误最终答案四种候选及逐条评分。
- `*.ranking.jsonl`：同一样本的非平分偏好对；通过 sample_id 和轨迹名称关联完整轨迹。
- `manifest.json`：生成器版本、配置、实际分布、轨迹来源、文件行数及 SHA-256；完整导出后才发布目录。

所有样本保留 `synthetic=true`；训练消息不包含 expected、样本族名称、变换标签或私有失败状态。
原始证据库不会自动导入这些文件。现有训练脚本有固定输入位置，本组件不覆盖它们；
使用时须显式选择对应训练文件，不把 validation、test、ood 拼入训练集。
不要混合具有不同切分配置的数据版本并据此声称无泄漏。
当前 Grader 正例覆盖 sufficient／partial，不覆盖 irrelevant 的全部情形；
它是补充数据组件，不是完整的 Grader、法律推理或规划训练集。

奖励只在答案正确且所有步骤有效时给出：`1 - 0.1 * min(调用数 / 参考调用数, 2)`，否则为零。
每条轨迹同时保存独立质量标志，不能只看最终成功或把所有中间步骤都当正确。
固定奖励范围避免不同任务的原始量纲主导混合训练；当前不做分位数拟合或 GRPO 组内归一化。
回归与排序训练本身不在此组件中实现，导出的分数和偏好可供后续独立训练代码读取。

## 验证口径

`tests/test_synthetic_data.py` 覆盖配置边界、可复现性、组隔离、复述／冲突、算术、
失败重试、正确答案下的错误步骤、标签独立复算、文件哈希和失败不发布。
生成器导出时逐个回放参考轨迹，失败即终止，不静默丢样本。
实际执行记录见 [本次验证记录](validation/synthetic_data_2026-10-21.txt)。

这些检查验证组件契约和虚构环境内的一致性，不验证模型训练收益。
OOD 仅覆盖当前生成器的工具命名和问题表述变化，不代表业务分布外泛化；
主题偏斜也不等于复现预训练模型中的参数记忆机制。不同生成规则和目标任务的效果应分别测量。
